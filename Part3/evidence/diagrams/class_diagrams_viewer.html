Design Pattern Identification and Evolution in a Spring Boot-Based E-Commerce Application

1. Strategy Pattern — Payment Module Selection

Key Architectural Notes:
  • Common Abstraction: Java uses interface PaymentMethod; Python, JS, and C++ use PaymentStrategy.
  • Standalone Implementations: Built-in strategies are CardPayment and UPIPayment.
  • RazorpayPayment Distinction: Shopizer's production RazorpayPayment belongs to the Part 2 application (sm-core/.../RazorpayPayment.java implementing PaymentModule). In standalone Part 3, it is labelled and used strictly as a conceptual extension fixture to verify OCP.

2. Observer Pattern — Order Status SMS Notification

Key Architectural Notes:
  • Observer Contract: Named OrderStatusListener in Java and C++, and OrderStatusObserver in Python and JavaScript.
  • Subject Responsibilities: OrderStatusService coordinates state machine transitions; EventPublisher manages subscriber collections and dispatches notifications defensively.
  • Concrete Observers: OrderStatusSmsListener filters for qualifying statuses (SHIPPED, DELIVERED) and delegates SMS dispatch; AuditObserver logs history.
  • SPI Decoupling: SmsProvider interface isolates notification policy from transport. UnconfiguredSmsProvider safely reports lack of provider credentials; RecordingSmsProvider captures invocations for unit assertions.
